# سيرفر إدارة قنوات تيليجرام

سيرفر يعمل دون واجهة ويب على Vercel. يستقبل منشورات قنوات ومجموعات المصدر عبر Telegram Webhook، ويحللها بقواعد برمجية، ويضيف العمولة، ثم ينشرها تلقائيًا في قنوات القسم نفسه.

يدعم الآن **Groq API مباشرةً لتحليل النصوص وصور المنتجات**، مع قواعد برمجية عند تعطيل AI. تخزين الإعدادات الحالي ما زال في تيليجرام دون قاعدة بيانات خارجية. إدخال Groq لا ينقل المشروع تلقائيًا إلى VPS.

## استخدام البوت

افتح المحادثة الخاصة مع البوت وأرسل `/start`. الواجهة والأزرار والرسائل بالعربية.

1. اضغط **إضافة قسم**، واكتب الاسم، واختر العملة.
2. اضغط **إضافة قناة**، واختر **مصدر (استقبال)**، ثم القسم والقناة.
3. أضف قناة أخرى من نوع **وجهة (نشر)** إلى القسم نفسه.
4. عند إضافة وجهة النشر، سيطلب البوت **العمولة** ثم **صيغة المنشور النهائي**.
5. راجع المثال واضغط **حفظ القناة**. تُطبّق الإعدادات على المنشورات الجديدة مباشرة دون إعادة نشر السيرفر.

يمكن تحديد القناة من منتقي تيليجرام، أو إرسال اسمها `@username`، أو معرّفها الرقمي، أو تحويل منشور منها إذا كان مصدر التحويل ظاهرًا. أضف البوت إلى القناة أولًا.

تتيح القائمة عرض القنوات والأقسام، وتعديل عمولة الوجهة وصيغتها، وحذف القنوات بعد التأكيد، وعرض حالة آخر محاولات النشر. لحذف المصدر من قسم أو نقله إلى قسم آخر، احذفه من البوت وأضفه مجددًا. حذف القناة من البوت لا يحذفها من تيليجرام.

## العمولة والصيغة

- `10%` أو `١٠٪`: إضافة نسبة 10٪ إلى سعر المورد؛ 100 يصبح 110.
- `50`: إضافة مبلغ ثابت بعملة القسم؛ 100 يصبح 150.
- `0`: النشر بسعر المورد.

الحقول المتاحة في الصيغة:

| الحقل | المعنى |
| --- | --- |
| `{المحتوى}` أو `{الوصف}` | وصف المورد بعد إزالة السعر الذي تم التعرف عليه |
| `{السعر}` | سعر البيع بعد العمولة، وهو حقل مطلوب |
| `{العملة}` | عملة القسم |
| `{القسم}` | اسم القسم |
| `{سعر_المورد}` | السعر الأصلي |
| `{العمولة}` | قيمة العمولة المحسوبة |
| `{اسم_المنتج}` | الاسم المكتوب أو أول سطر وصفي |
| `{الموديل}` | الموديل عند وجود تسمية واضحة |
| `{اللون}` | اللون عند وجود تسمية واضحة |
| `{المقاس}` | المقاس عند وجود تسمية واضحة |
| `{السعة}` | السعة المكتوبة أو القيم بوحدات GB/TB/جيجا/تيرا |
| `{الحالة}` | حالة المنتج عند وجود تسمية واضحة |
| `{الكود}` | كود المنتج |
| `{الخامة}` | خامة الملابس |
| `{وحدة_السعر}` | للقطعة أو للطقم أو للدستة أو للعبوة |

مثال:

```text
🛍 {اسم_المنتج}
{المحتوى}

💰 السعر: {السعر} {العملة}
📦 قسم {القسم}
```

الحقول غير الموجودة تظهر فارغة وتُحذف أسطرها من القالب. في وضع Groq يُطلب وصف عربي مختصر دون تخمين الخامة أو المقاسات أو العلامات التجارية؛ أسماء العلامات والأكواد تُحفظ كما هي. تبقى نتائج AI احتمالية وتحتاج اختبارًا بعينات الموردين. تُرسل الصيغة كنص عادي دون HTML. العمولة هي زيادة على سعر المورد، وليست حساب هامش ربح من سعر البيع.

## تحليل Groq للنص والصورة

1. ضع المفتاح في `.env.local` المحلي، في السطر `GROQ_API_KEY=`. هذا الملف مستبعد من Git ولا يُرفع للمستودع.
2. للسيرفر المنشور، يُحفظ المفتاح كمتغير سري `GROQ_API_KEY` في بيئة Production على Vercel، ثم يعاد النشر. وجود الملف على جهازك وحده لا يغيّر متغيرات Vercel.
3. يبدأ وضع Groq تلقائيًا عند وجود المفتاح. يمكن ضبط `AI_PARSING_ENABLED=false` لاستخدام القواعد فقط. إذا ضُبطت القيمة `true` دون مفتاح، يتوقف التحليل برسالة إعداد واضحة.
4. افتح البوت واختر **إعدادات التحليل** لعرض حالة الإعداد، ثم **تجربة التحليل** وأرسل نصًا أو صورة منتج. لا تحتاج قناة نشر لتجربة قالب الملابس.
5. عند إضافة وجهة نشر أو تعديلها، اختر **قالب ملابس جاهز** أو أرسل قالبك الخاص.

الإعدادات الحالية القابلة للتغيير:

| المتغير | القيمة الافتراضية |
| --- | --- |
| `GROQ_TEXT_MODEL` | `openai/gpt-oss-120b` عبر Groq مباشرةً |
| `GROQ_VISION_MODEL` | `qwen/qwen3.8-27b` عبر Groq مباشرةً |

تم التحقق من توفر النموذجين بمفتاح الحساب وقت التنفيذ. نموذج الصورة مُدرج ضمن نماذج Groq التجريبية؛ قد تتغير إتاحته، ويمكن تغيير الاسم عبر متغير البيئة. لا يستخدم التطبيق Vercel AI Gateway أو مفاتيح OpenAI لهذا التكامل.

يستخرج المحلل اسم المنتج والوصف والكود والموديل والخامة والألوان والمقاسات والسعة والحالة وسعر المورد وعملته ووحدته. يُطلب حذف أسعار المورد وبيانات التواصل والدفع من الوصف المولد. يحسب السيرفر العمولة والسعر النهائي بالكود بعد التحقق؛ لا يترك الحساب للنموذج.

تتوقف المنشورات للمراجعة عند غياب السعر أو دليله، أو اختلاف السعر الصريح عن المستخرج، أو انخفاض الثقة المقدرة عن 85٪، أو اختلاف العملة، أو غموض وحدة السعر، أو إرجاع تحذيرات. درجة الثقة ليست ضمانًا للدقة. سعر الدستة أو الطقم لا يُقسم تلقائيًا، وتضاف وحدة السعر إلى القوالب القديمة إذا لم تتضمن حقلها.

توجد طبقة تحقق مستقلة من نص المورد قبل السماح بالنشر: تقارن الأسعار الصريحة ووحداتها، وتوقف الأسعار المتعددة لنفس الوحدة وشروط الجملة/المشكل، وتراجع العملات والأكواد الصريحة بما فيها الأصفار الأولى، وتمنع تحويل نطاق وزن إلى مقاس رقمي بلا وحدة وزن. تعمل هذه الفحوص أيضًا عند إرفاق صورة؛ الصورة لا تلغي تعارض النص. عند غياب العملة يمكن استخدام عملة القسم. هذه قواعد للنصوص المدعومة وليست فهمًا شاملًا لكل صيغ الموردين؛ قراءة محتوى الصورة تظل معتمدة على النموذج، ولا تمثل الثقة العالية ضمانًا لصحتها.

تُحمّل صورة تيليجرام في ذاكرة السيرفر ثم تُرسل بايتاتها إلى Groq؛ لا يُرسل رابط تحميل تيليجرام الذي يحتوي رمز البوت. الحد المحلي للصورة 8 ميجابايت. يُحلل أكبر مقاس للصورة المرسلة كصورة Telegram. لا يوجد تحليل إطارات فيديو أو PDF أو صور مرسلة كمستندات، ولا تجميع ألبومات.

يفرض التطبيق مهلة 40 ثانية وطلبًا واحدًا دون محاولات AI تلقائية. عند خطأ المفتاح أو الرصيد أو حدود المعدل أو رد غير صالح، يتوقف المنشور مع تنبيه بدل النشر بناءً على تحليل جزئي. إعادة إرسال منشور نُفذت محاولاته الحديثة لا تعيد طلب AI. لا يوجد طابور دائم لإعادة محاولة التحليل لاحقًا.

في وضع Groq تُرسل النصوص والصور إلى Groq لمعالجتها وتُحتسب وفق حسابك وحدود النموذج. لا يشتري التطبيق رصيدًا أو يغير خطة الحساب. مفاتيح API لا تُحفظ في إعدادات تيليجرام ولا تُكتب في السجلات.

اختبار محلي بمحتوى تجريبي:

```sh
npm run check:groq
node --env-file=.env.local scripts/check-groq.mjs --image /absolute/path/product.png
```

المراجع: [صور Groq](https://console.groq.com/docs/vision)، [المخرجات المنظمة](https://console.groq.com/docs/structured-outputs)، [النماذج](https://console.groq.com/docs/models).

## التحليل بالقواعد البرمجية

أمثلة مدعومة:

```text
هاتف سامسونج A55
اللون: أسود
السعة: 128 GB
السعر: ١٥٠٠ جنيه
```

```text
Product: Cotton shirt
Size: XL
Color: Blue
Price: 350 EGP
```

يمكن التعرف على سطر مستقل مثل `450 جنيه`، أو سعر مكتوب بعد وصف وفاصل مثل `سماعة | السعر: 300 جنيه`. تُقبل الأرقام العربية والفارسية والإنجليزية وفواصل الآلاف الصحيحة. تتعرف القواعد على تسميات عربية وإنجليزية للمعلومات، دون إرسال المحتوى إلى خدمة خارجية عندما يكون وضع القواعد البرمجية فقط مفعّلًا.

إذا لم يوجد سعر واضح، أو وُجدت أسعار مختلفة، لا ينشر البوت المنشور وينبه المالك. لا يدعم السعر المكتوب بالكلمات أو تخمين أسعار من أرقام الموديلات. المحتوى غير المنظم قد يحتاج قواعد إضافية اعتمادًا على عينات الموردين. لا تُزال بيانات التواصل وروابط المورد تلقائيًا؛ استخدم صيغة تعتمد على الحقول المطلوبة إذا كنت لا تريد الوصف الكامل.

## قنوات الملابس وتجربة التحليل

يعرض زر **قنوات ملابس مقترحة** خمس قنوات عامة اكتُشفت من صفحات تيليجرام المنشورة: اللؤلؤة، تيكي تاكا، Akira، شيماء هوم وير، ومصنع S M. الروابط والتصنيفات ومصادر المعاينة محفوظة في `data/channel-candidates.js`، بتاريخ بحث 29 أكتوبر 2026. الأوصاف مأخوذة من تعريف القنوات لنفسها، وليست تحققًا من موثوقية البائعين. ليست القنوات مصادر مفعلة ولا تتم مراسلة أصحابها تلقائيًا.

الاطلاع على صفحات عامة لا يمنح البوت صلاحية استقبال تحديثاتها؛ أضف البوت بإذن إدارة المصدر، ثم سجله من المحادثة. لا يوجد هنا جامع يعمل بحساب مستخدم أو حل يتجاوز صلاحيات تيليجرام.

بعد إضافة وجهة نشر، اضغط **تجربة التحليل**، واختر الوجهة، ثم أرسل نموذج منشور. يعرض البوت المعلومات المستخرجة والسعر بعد العمولة والصيغة النهائية، دون نشر أي شيء للقنوات.

## حفظ الإعدادات دون قاعدة بيانات

يحفظ البوت إعداداته في **رسالة مثبتة في المحادثة الخاصة مع المالك**، ويقرأها من تيليجرام عند وصول كل تحديث. تشمل الإعدادات الأقسام والقنوات والصيغ والعمولات والخطوة الحالية للإعداد وآخر 24 محاولة نشر. لا يوجد PostgreSQL أو Redis أو ملف محلي دائم.

الرسالة موقعة لمنع التلاعب ومضغوطة لتقليل حجمها؛ التوقيع لا يشفر محتواها. لا تحتوي على رمز البوت. احتفظ بها مثبتة ولا تحذفها أو تثبت رسالة أحدث منها. إذا ثبتّ رسالة أخرى، أزل تثبيت الرسائل الأحدث لاستعادة وصول البوت إلى رسالة الإعدادات. إذا فقدت الرسالة، أرسل `/initialize` لبدء إعدادات فارغة، ثم أضف الأقسام والقنوات مجددًا. هذا الأمر يعيد الضبط، ولا يستعيد إعدادات مفقودة.

لا تغيّر `WEBHOOK_SECRET` بعد إنشاء الإعدادات دون التخطيط لإعادة تهيئتها؛ فهو مفتاح التحقق من توقيع الرسالة أيضًا.

هذه وسيلة مناسبة للاستخدام المحدود. الحد الحالي 20 قناة و10 أقسام و3 وجهات نشر لكل قسم، بشرط أن تتسع الإعدادات في رسالة تيليجرام واحدة. قد يقل الحد العملي مع الصيغ الطويلة. الاحتفاظ بتاريخ كامل أو التعامل مع تدفق كثيف يحتاج تصميم تخزين مختلفًا.

## صلاحيات تيليجرام

- أنشئ البوت من `@BotFather` وأضفه إلى قنوات المصدر والوجهة.
- امنحه صلاحية نشر الرسائل في قنوات الوجهة.
- في مجموعات المصدر، اجعله مشرفًا أو عطّل وضع الخصوصية من BotFather. قد تحتاج إلى إزالة البوت وإضافته مجددًا بعد تغيير الخصوصية.
- يستطيع البوت استقبال ما تسمح له صلاحيات تيليجرام بقراءته فقط. لا يمكنه قراءة قناة عشوائية لمجرد معرفة اسمها، ولا يجلب الأرشيف القديم.
- قد لا يرى رسائل البوتات الأخرى. لا ينسخ المحتوى المحمي.

## المشروع المنشور

- المستودع الخاص: https://github.com/mahmoud2391997/telegram-bot-multi-stores
- فحص السيرفر: https://telegram-bot-multi-stores.vercel.app/api/health
- إعدادات متغيرات Vercel: https://vercel.com/iti1/telegram-bot-multi-stores/settings/environment-variables

البوت الحي: [مدير قنوات الملابس](https://t.me/ClothesStoresManager_bot). تم إنشاء البوت وربطه بالسيرفر وتعيين حساب المالك. جميع متغيرات الإنتاج مضبوطة، والرمز محفوظ كمتغير سري في Vercel. افتح البوت وأرسل `/start`، ثم أضف الأقسام والقنوات من المحادثة. لا ترسل الرمز في المحادثة أو تضعه في المستودع.

لربط Telegram بعد إعادة النشر، ضع `BOT_TOKEN` و`APP_URL` فقط في ملف `.env` المحلي، واترك `WEBHOOK_SECRET` فارغًا، ثم نفّذ `node --env-file=.env scripts/setup.mjs`. يتصل السكربت بمسار `/api/setup` باستخدام رمز البوت، بينما يظل رمز استقبال المنشورات محفوظًا في Vercel. عند النجاح يعرض اسم البوت؛ افتحه وأرسل `/start`. لا يعتمد هذا المسار على وصول غير مصادق، ولا يكشف الرموز في الاستجابة.

فحص الصحة يعرض حاليًا `configured: true`. تم اختبار رسالة البداية، وحفظ الإعدادات المثبتة، وعرض القنوات المقترحة في البوت الحي. ما زال اختبار استقبال منشور ونشره إلى قناة فعلية يحتاج إضافة مصادر ووجهات يملك المستخدم صلاحية الوصول إليها.

## التشغيل على Vercel

1. استورد المشروع في Vercel بإطار عمل **Other** ودون أمر بناء. يتطلب Node.js 22.
2. أضف متغيرات البيئة الموجودة في `.env.example`:

   | المتغير | الاستخدام |
   | --- | --- |
   | `BOT_TOKEN` | رمز البوت من BotFather |
   | `OWNER_ID` | معرّف المستخدم المالك الرقمي، وليس اسم المستخدم |
   | `WEBHOOK_SECRET` | قيمة عشوائية من 16 إلى 256 حرفًا إنجليزيًا أو رقمًا أو شرطة أو شرطة سفلية |
   | `APP_URL` | عنوان الإنتاج مثل `https://your-project.vercel.app` |

   يمكن إنشاء قيمة سرية باستخدام `openssl rand -hex 32`.
3. انشر المشروع. يجب أن يستطيع تيليجرام الوصول إلى `/api/webhook` دون صفحة تسجيل دخول Vercel. يوفر `/api/health` فحصًا لوصول السيرفر فقط، وليس تحققًا من صلاحيات البوت أو الإعدادات.
4. على جهازك، انسخ `.env.example` إلى `.env` واملأ نفس القيم. لا ترفع الملف أو الرموز إلى Git.
5. نفّذ:

   ```sh
   npm ci
   node --env-file=.env scripts/setup.mjs
   ```

   يسجل هذا الأمر عنوان استقبال التحديثات ويضبط قائمة أوامر البوت بالعربية. لا ينشئ موارد خارجية أو قاعدة بيانات. لا تستخدم الرمز نفسه لبوتين أو عنواني استقبال مختلفين؛ تيليجرام يسمح بعنوان Webhook واحد لكل بوت.
6. افتح البوت وأرسل `/start` ثم أضف القسم والقنوات من الأزرار.

المستودع والسيرفر والبوت منشورون ومربوطون كما هو موضح أعلاه. يمكن استخدام الخطوات العامة أعلاه لنشر نسخة مستقلة. تتوفر أيضًا صفحة `/activate.html` لتسجيل Webhook عبر نموذج POST، وتحديد معرّف المالك من رسالة `/start` عند الإعداد الأول فقط؛ تتطلب رمز البوت ولا تضعه في عنوان URL أو تعيده في الاستجابة. لا تغيّر رمز استقبال المنشورات الخاص بالنسخة المنشورة بعد إنشاء إعدادات البوت.

## سرعة النشر وحدود الاعتمادية

- يبدأ النشر تلقائيًا عند وصول التحديث، دون جدولة أو خطوة موافقة لكل منشور. يعتمد وقت الوصول على تيليجرام وVercel وحدود المعدل؛ لا يوجد ضمان زمني ثابت.
- تُسجل محاولة الإرسال في الرسالة المثبتة قبل الاتصال بوجهة النشر. يتجاهل البوت المحاولات الحديثة المسجلة عند إعادة إرسال التحديث.
- عند انقطاع الشبكة أثناء الإرسال، لا يعيد البوت المحاولة تلقائيًا حتى لا يكرر منشورًا ربما وصل بالفعل. يفحص المالك الوجهة ويعيد النشر يدويًا إذا لزم الأمر.
- هذا ليس ضمانًا للنشر مرة واحدة بالضبط: السجل محدود بـ24 محاولة، ولا توجد معاملات ذرية أو طابور دائم. يمكن أن يحدث تكرار مع التحديثات القديمة أو المتزامنة، ولا توجد إعادة تشغيل آلية للمنشورات الفاشلة.
- يضبط إعداد Webhook اتصالًا واحدًا لتقليل التزامن. تحديث الرسالة المثبتة لكل محاولة يخضع لحدود Telegram API، لذا هذا التصميم مناسب للحجم المنخفض، وليس تدفقًا كثيفًا أو عددًا كبيرًا من الوجهات.
- تُدعم المنشورات النصية والصور والفيديو. الألبوم يُعالج كمنشورات مستقلة. لا تُدعم المستندات والصوت والاستطلاعات أو مزامنة التعديلات والحذف.
- الحد الأقصى للنص النهائي 4096 حرفًا، ولوصف الصورة أو الفيديو 1024 حرفًا. يُتجاوز المحتوى الأطول مع تنبيه المالك.
- تتم إدارة البوت من محادثة المالك الخاصة فقط. خطوات الإعداد تنتهي صلاحيتها بعد 30 دقيقة. لا تُكتب الرموز أو نصوص الموردين في سجلات السيرفر.

## الاختبار

```sh
npm test
```

تتحقق الاختبارات من عينات منشورات مصطنعة بالعربية والإنجليزية، وحساب العمولة، والحقول، وصلاحيات المالك، وخطوات إضافة القنوات وتعديلها وحذفها، والنشر النصي والمصور، والتوقيع، وتجنب تكرار المحاولات الحديثة. تستخدم محاكاة Telegram API ولا تثبت نجاح الربط الحي.

قبل الاستخدام الفعلي، جرّب قناة مصدر ووجهة خاصتين: أضفهما من البوت، واضبط العمولة والصيغة، وانشر نصًا وصورة، ثم تحقق من السعر والوجهة. راقب سجلات Vercel و`getWebhookInfo` للتأكد من وصول التحديثات. تحقق أيضًا من أن البوت يستطيع قراءة رسالة الإعدادات المثبتة وتعديلها في محادثتك الخاصة.

المراجع: [وثائق Telegram Bot API](https://core.telegram.org/bots/api)، [صلاحيات استقبال رسائل البوت](https://core.telegram.org/bots/faq)، [دوال Node.js على Vercel](https://vercel.com/docs/functions/runtimes/node-js).

تعمل الاختبارات تلقائيًا ضمن أمر بناء Vercel (`npm test`) قبل نشر كل تحديث من GitHub. لم تبدأ محاولة GitHub Actions الأولية وأرجعت المنصة `startup_failure` دون وظائف أو تشخيص تفصيلي؛ لذلك لا يعتمد المشروع على GitHub Actions، وتمت إزالة ملفه الاختياري واستخدام تحقق بناء Vercel بدلًا منه.
